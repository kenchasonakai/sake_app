# デザインの論点

見せ方と言葉の論点。画面の設計は [screens.md](screens.md)、流れは [flows.md](flows.md)。決まったものは decisions.md の D 番号を付けた。

## 1. 言葉づかい（最重要）

主役は日本酒を知らない人。画面の語彙がそのまま製品の個性になる。

- 用語を本文に出さない。純米、吟醸、精米歩合、日本酒度は、詳細を開いた時だけ。
- 味の軸の言い換え
  - 甘口〜辛口 → 「甘め」〜「すっきり辛め」
  - 淡麗〜濃醇 → 「軽やか」〜「コクあり」
  - 知名度 → 「定番」〜「知る人ぞ知る」
- 候補の説明は 4 文以内。どんな味か、どんな立ち位置か、事実（ファンが多い、出回りが少ない、蔵が新しい）、こんな人に。
- 語彙のトーンはすべて丁寧語（D19）。LINE に貼る定型文も揃える。

## 2. 贈る流れ

- 画面は場面と予算、候補、一言の 3 つを軸にし、サインインと確定はその後ろに置く。
- 好みのヒントは場面と予算の画面の折りたたみに置く。「分からない」が既定であることが見て分かるように。
- 候補は予算内のものをすべて出し、1 枚ずつめくる。先頭の 2 枚におすすめの印（定番と定番以外）を付ける（D20、D21）。
- 一言は、決めた理由をチップで選ぶと下書きができ、編集できる。自由入力から始めない。
- 受け取りページに出す名前を一言の画面で決める。既定はアカウントの表示名。
- サインインを確定の直前に置くので、そこで離脱しないよう、入力した内容が残ることを見せる。

## 3. 共有

- リンクと LINE 用の定型文を 1 タップでコピーできる。
- 定型文は「日本酒を一本お贈りしました。こちらのリンクからご住所を入力いただくと届きます。」程度の短さ（D19）。一言はリンク先で読ませる。
- 決めること: OS の共有シートも出すか、LINE 向けのコピーだけにするか。

## 4. 受け取りページ（Web、JS なし）

- 並び: 贈る人の名前と一言、一本の説明、受け取るフォーム、届いた後にできること。
- 20 歳以上の確認は、フォームの先頭のチェックボックス。ページを開いた瞬間の全画面確認はしない（離脱を増やさない）。
- 住所フォームは一般的な形（D8）。郵便番号からの住所補完は付けない（JS なしのため）。
- 20 歳未満の飲酒禁止の表示と、デモで実際には届かないことの注記は定型文で置く（D16）。
- 状況ページは配送状況が主役で、アプリの案内は下に小さく。
- 使えなくなったリンクの画面も用意する。期限切れとキャンセルで同じ文面にする（D12）。
- 断るボタンは置かない（D13）。

## 5. 記録（アプリ）

- 記録は自分のための出会いの記録（D3）。見返しやすさを優先する。
- 入力は 3 タップで終える。「また飲みたい」「ふつう」「合わなかった」と任意の一言。星や点数は使わない。
- もらった一本の初回記録では「贈った人に『開けたよ』を送る」の切り替えを出す（D4）。感想は送られないことを 1 行で書く。
- 決めること: 開けたよの切り替えの既定（オンかオフか）。
- 一覧は、もらった一本と自分で飲んだ酒を 1 本の時系列に並べ、印で区別する案。

## 6. 見た目

- ギフト EC を基調に差し色で藍を少し。書体は Zen Kaku Gothic New、本文は 16 以上（D22）。色の値は screens.md。
- 画像は、瓶の実写だとラベルの権利と撮影の手間がある。イラスト、通販サイトなどの商品写真、画像なしのどれでも成り立つようにする。
- ダークモードに対応する。受け取りページも追従する。

## 7. 運営画面（O4）

次に画面のイメージを話してモックを作る。手配の状態を手で進めることがデモの操作そのものになる（D14）。

## 8. 決めていないこと

1. 共有の出し方（screens.md では、文章ごとコピーと OS の共有シートの両方を置く案）
2. 開けたよの切り替えの既定（オンかオフか）
3. 画像の用意（イラスト、商品写真、なし）
4. アプリ名
5. 予算の区切り。カタログに小瓶だけを入れるか、四合瓶も入れるかで決まる（[research/prices.md](research/prices.md)）
6. 運営画面（screens.md の M1〜M3 がたたき台）
