# 決定事項と未決事項

コンセプト（[concept.md](concept.md)）から設計に落とす時に決めたこと、まだ決めていないことの一覧。設計ドキュメントはすべてこの表に従う。食い違ったらこの表を直してから他を直す。

## 前提

- ハッカソンの題材。デモで体験が伝わることを優先する。
- 法務・決済・物流の本番対応は後で詰める。ただし、後から本番化できなくなる作りは避ける。

## 決定

| # | 内容 | 理由 |
| --- | --- | --- |
| D1 | 贈る人は、ギフトを確定する前に会員登録とサインインをする。匿名ログインは使わない。候補を見るところまではログイン不要。 | 贈る人には状況の通知と「開けたよ」を届ける宛先が要る。匿名アカウントの引き継ぎという複雑さを持ち込まない。 |
| D2 | 受け取る人はアカウントなしで受け取れる。リンクを開いて住所を入れるだけ。 | 友人の輪に広げるため。受け取りの手間を増やさない。 |
| D3 | 記録は本人だけのもの。日本酒と出会った記録で、自分で見返す、自分で選ぶ時の基準に使う。ギフトの候補選びには使わない。 | 贈りものは贈る人の気持ちが大事で、相手にとって新しいか、昔飲んだことがあるかは問わない。何度も飲みたいなら自分で買えばよい。 |
| D4 | 「開けたよ」は任意。受け取った一本を記録する時に、送るかどうかを本人が選ぶ。 | 手応えではあるが、受け取る人に義務を感じさせない。 |
| D5 | GET リクエストで状態を変えない。 | LINE のリンクプレビューやセキュリティスキャナが、人より先にリンクを開く。 |
| D6 | 期限は `*_expires_at` 列とリクエスト時の比較で判定する。期限切れを定期実行で書き換えない。 | 仕組みが単純。定期実行は住所の削除など、リクエストが来なくても起きるべき処理にだけ使う。 |
| D7 | （仮）公開の入口を 1 つにする。アプリもブラウザも Web の Worker にだけ話し、`/api/*` は Web がサービスバインディングで API に渡す。API の Worker は公開しない。 | オリジンが 1 つになり、CORS も Cookie の扱いも単純になる。独自ドメインがなくても workers.dev のまま成り立つ。独自ドメインは後から Web の Worker に付けるだけ。 |
| D8 | 住所フォームは一般的な形にする。郵便番号、都道府県、市区町村、番地、建物名、氏名、電話番号。 | 画面設計の前に決め打ちしてよい部分。 |
| D9 | Web とアプリは最終的にどちらもフル機能。最初はアプリと、Web の受け取りリンクだけを作る。 | ギフトを探す段階でアプリを入れさせないのが Web の役割。まずアプリで体験を作る。 |

## 未決（相談したいこと）

### O1. お金と手配の流れ

誰が代金を受け取り、誰が酒を買って送るか。データモデルは手配の方法を切り替えられる形にしておき、ここが決まるまで決済は作らない。

| 案 | 中身 | 良い点 | 課題 |
| --- | --- | --- | --- |
| A. デモ専用 | 決済なし。受け取りで注文データができ、運営が手配する。実際には送らないデモもあり。 | 最速。体験の流れだけを見せられる。 | 本物の注文は回らない。 |
| B. 運営が代わりに買って送る | 贈る人から代金を受け取り、運営が Amazon や楽天などで探して買い、相手の住所に直送する。 | 提携先が要らない。品揃えが広い。 | 代金を預かって酒を買い届ける構造は、本番化では免許の確認が必須。通販サイトのギフト設定（金額を伏せる、包装）は商品ごとに違う。小瓶の取り扱いが少ない。 |
| C. 既存のソーシャルギフトに渡す | 選ぶ、一言を書くまでをこのアプリで行い、購入と住所入力は住所不要で贈れる既存のギフトサービスに任せる。 | 決済も住所も持たない。 | 受け取りページと「開けたよ」が自分たちの体験から外れ、コンセプトの中心が崩れる。候補が相手先の取扱商品に縛られる。 |
| D. 提携酒販店が決済と発送 | 店が贈る人から代金を受け取り、こちらは住所を渡すだけ。 | 本番化の筋が一番良い。 | 提携先探しが要り、ハッカソンには重い。 |

推奨: ハッカソンは A で作り、デモの見せ方次第で B を手動で回す。データは D に移れる形にしておく。C はコンセプトと相性が悪い。

### O2. 送料と予算

| 案 | 中身 |
| --- | --- |
| 予算は商品価格だけ | 送料は別に表示する。贈る人の想定より支払いが増える。 |
| 予算は届くまでの総額 | 送料込みで絞る。贈る人に分かりやすい。 |
| 送料込みの商品だけを候補にする | 単純だが、小瓶では候補が減る。 |

推奨: 贈る人に聞く予算は「届くまでの総額」にする。カタログに価格と送料の目安を持ち、合計で絞る。ハッカソンでは送料を一律の目安値にしてよい。

### O3. 法定表示と同意文

ハッカソンでは定型文で置き、本番前に確認する。

- 酒の購入につながる画面（候補、受け取りページ）に「20歳未満の者の飲酒は法律で禁止されています」を表示する。
- 受け取りフォームに、住所を発送のために手配先へ渡すことへの同意文を置く。手配先の書き方は O1 で決まる。
- プライバシーポリシーは雛形を置く。

### O4. 運営画面

O1 が決まったら、画面のイメージを話してモックを作る。置き場所の候補は Web の Worker のサーバー描画で、Cloudflare Access で守れば管理者向けのログインを作らずに済む。
