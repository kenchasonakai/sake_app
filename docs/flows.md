# 利用の流れ

登場人物は 3 人。

- **贈る人**: 日本酒を知らない。アプリ（Expo Go）で選んで贈る。会員登録が要る（D1）。
- **受け取る人**: 日本酒好きの友人。リンクを開いて住所を入れるだけ。アプリは任意（D2）。
- **運営**: 受け取りが確定したギフトの手配の状態を、運営画面から手で進める。実際に買うことも送ることもしない（D14）。

## 1. 贈る（アプリ）

| # | 画面 | すること | ログイン |
| --- | --- | --- | --- |
| G1 | ホーム | 「贈る」を押す | 不要 |
| G2 | 場面と予算 | 場面（誕生日、お礼、なんとなく）と予算の区切りを選ぶ。相手の好みは折りたたみの中で任意。既定は「分からない」 | 不要 |
| G3 | 候補 | 予算内の候補を 1 枚ずつめくって読む。先頭の 2 枚はおすすめ（定番と定番以外）。用語を使わない説明、味の方向、定番か知る人ぞ知るか、事実（ファンが多い、出回りが少ない、蔵が新しい）。1 本を選ぶ（D20、D21） | 不要 |
| G4 | 一言 | 決めた理由をチップで選ぶと、一言の下書きができる。編集できる。受け取りページに出す自分の名前と、自分だけに見える相手のメモを書く | 不要 |
| G5 | サインイン | 未ログインならここで会員登録とサインイン。20 歳以上の自己申告 | ここで必要 |
| G6 | 確認と確定 | 一本、一言、名前、価格の目安を確認して確定する。ギフトとリンクができる。デモのため購入も発送も行われないことを明記する（D14） | 必要 |
| G7 | 共有 | リンクと LINE 用の定型文をコピーする | 必要 |
| G8 | ギフトの状況 | 受け取り待ち、受け取られた、手配、発送、届いた、開けたよ | 必要 |

- G2〜G4 の入力は端末の中だけに持ち、サーバーには G6 で初めて保存する。候補の計算は未ログインでも API に頼める。
- G8 からできること
  - リンクの再表示
  - リンクの作り直し。受け取られる前ならいつでも。違う人に送った時や期限が切れた時に使う。古いリンクは使えなくなる（D11）
  - キャンセル。受け取られる前だけ（D10）。選び直したい時は、キャンセルして新しく贈る

### 贈る人に見せる状況

| 内部の状態 | 表示 |
| --- | --- |
| ギフト issued、期限内 | 受け取り待ち |
| ギフト issued、期限切れ | 期限切れ。リンクを作り直せます |
| ギフト claimed、手配 pending | 受け取られました。手配しています |
| 手配 arranged | 手配しました |
| 手配 shipped | 発送しました |
| 手配 delivered | 届きました |
| ギフト cancelled | キャンセルしました |
| `opened_at` あり | 上の表示に「開けたよが届きました」を併記 |

贈る人には、受け取る人の住所、メール、アカウントの有無、記録の中身を一切見せない。

### 贈る人への知らせ

受け取られた、発送した、届いた、開けたよ、の変化はアプリ内で見せる（D18）。ホームの贈ったギフト一覧で、最後に見た時より新しい変化に印を付ける。最後に見た時刻は端末に持ち、サーバーには書かない。画面を開いた時と引っ張って更新した時に最新にする。プッシュ通知は前提にしない。

## 2. 受け取る（Web、アカウント不要）

| # | 画面 | すること |
| --- | --- | --- |
| R1 | LINE のプレビュー | 「日本酒が届きます」程度だけを出す。贈る人の名前と一言はプレビューに出さない |
| R2 | 受け取りページ | 贈る人の名前と一言、一本の説明、20 歳未満の飲酒禁止の表示、デモで実際には届かないことの注記（D16） |
| R3 | 受け取りフォーム | 20 歳以上の確認、住所、氏名、電話番号、任意のメールアドレス。実在の住所は不要と書く |
| R4 | 完了 | 「手配します」。同じリンクを開くと状況ページになる |
| R5 | 状況ページ | 手配中、発送、届いた。下にアプリでできることの案内（記録、開けたよ） |

### 受け取りページの出し分け

| ギフトとリンクの状態 | 出すもの |
| --- | --- |
| issued、期限内 | R2 と R3 |
| issued、期限切れ | 「このリンクは使えなくなりました。贈ってくれた人に確認してください」 |
| cancelled | 期限切れと同じ文面（D12） |
| claimed | R5 |
| リンクの有効期限切れ（受け取り後） | 完了したことだけ。一言や配送状況は出さない |
| トークンが存在しない。作り直し前の古いリンクもここに入る | 期限切れと同じ文面。HTTP のステータスは 404 |

- 表示は GET、住所の送信は同じパスへの POST（D5）。GET では閲覧の記録も含めて何も書き込まない。
- 住所の送信は 1 回だけ成功する。2 回目以降の送信は状況ページを返す。
- 受け取る人が断るボタンは置かない。受け取らなければ期限切れになる（D13）。
- JavaScript なしで完結させる。LINE のアプリ内ブラウザで開かれる前提。

### リンクの有効期限

トークンの有効期限は 1 つの列 `token_expires_at` で持ち、状態が進むたびに延ばす（D6）。

| 時点 | 有効期限 | 意味 |
| --- | --- | --- |
| 発行 | 発行から 30 日 | 受け取りの期限 |
| 受け取り | 受け取りから 90 日 | 状況の閲覧とアプリへの紐づけの期限 |
| 届いた | 届いた日から 30 日 | 同上 |
| 作り直し | 作り直しから 30 日 | 新しいトークンに替わり、古いリンクは無効 |
| キャンセル | 即時に無効 | |

## 3. 受け取る人がアプリを使い始める（提案、O5）

受け取る人が記録や「開けたよ」を使いたくなった時、受け取ったギフトを自分のアカウントに紐づける。紐づけは受け取り後、リンクの有効期限内だけできる。1 つのギフトに紐づくアカウントは 1 つ。

紐づけの経路は 2 つ用意する。リンクからアプリを直接開く方式は、Expo Go では使えないので採らない（D17）。

1. **メールアドレスで自動。** 受け取りフォームで任意のメールアドレスを入れていた場合、そのメールで会員登録したら自動で紐づける。メール OTP で本人確認済みのアドレスだけを使う。
2. **リンクを貼る。** アプリの「もらったギフトを追加」に受け取りリンクを貼る。

- 紐づけても贈る人には何も伝えない。受け取る人がアプリを使っているかどうかも贈る人には分からない。
- 紐づけたギフトは、アプリの記録画面に「もらった一本」として出る。

## 4. 記録（アプリ、要アカウント）

| # | すること |
| --- | --- |
| T1 | 一本を選ぶ。カタログから、もらった一本から、自由入力のいずれか |
| T2 | 評価を 3 段階で選ぶ（また飲みたい、ふつう、合わなかった）。任意で一言と日付 |
| T3 | もらった一本を初めて記録する時だけ、「贈った人に『開けたよ』を送る」の切り替えを出す（D4）。感想は送られないことを 1 行で書く |
| T4 | 保存。開けたよを選んでいれば、贈る人に 1 回だけ届く |

- 記録は本人だけが読める。運営も読まない。ギフトの候補選びには使わない（D3）。
- 「開けたよ」を後から送ることもできる。ギフトの詳細から 1 回だけ。

## 5. 自分で選ぶ（後回し）

自分の記録を基準に自分用の候補を出し、酒販店や蔵の EC へ外に出す。ギフトとは別の機能で、記録を使うのはここだけ。

## 6. 運営（D14、O4）

1. 受け取りが確定した注文を一覧で見る。
2. 手配済み、発送、届いた、の順に状態を手で進める。実際に買うことも送ることもしない（D14）。
3. 進めるたびに、贈る人のアプリの状況表示と、受け取りページの状況が変わる。

画面は、イメージを話してからモックを作る（O4）。
