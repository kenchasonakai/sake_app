# 引き継ぎメモ（新しいセッション向け）

これまでの設計（日本酒全般のギフトアプリ）はいったん捨て、岩瀬酒造のお題でゼロから考え直す。ここには、設計を捨てても使える情報だけを残す。詳しい出典は同じリポジトリの `docs/event.md`、`docs/research/iwase.md`、`docs/research/prices.md`。

## 1. お題（変更後）

- 千葉県御宿町の岩瀬酒造（銘柄「岩の井」）のこれからを、日本酒を呑みながら生成 AI で形にする会。
- 当日は庄野会長（庄野智紀さん）がオンラインで参加し、蔵の話と発表への講評がある。
- 制作は 14:50〜16:00 の約 70 分。16:25 から発表と講評。
- 成果物の形は自由。診断ツール、ラベル画像、ボット、企画書など。
- 課題は次から 1 つ選ぶ。
  1. 蔵のお酒を、飲んだことがない人に薦める
  2. 蔵の情報発信（SNS・サイト）を手伝う
  3. 蔵のお酒に合う料理を提案する
  4. 若い人が蔵のお酒を手に取る理由をつくる
  5. 蔵を訪ねたくなる仕掛けをつくる
  6. 海外の人にこの蔵を紹介する
- 告知には「当日までに考えてくると、その分つくる時間に回せる」とある。事前に作り込んでよいかは主催に未確認。

## 2. 岩瀬酒造（岩の井）の要点

- 創業 1723 年、300 年超。社員 8 人ほど。後継者不在で廃業寸前だった蔵を、先代の甥の庄野智紀さんが継いで立て直した。
- **国内屈指の硬い仕込み水。** 海に近く、貝殻層を通った地下水。硬度 240 とされる（別の単位で 13〜15 と書く記事もある）。主力シリーズ名「i240」はここから。
- **山廃仕込み**の割合が高い。**熟成古酒**にも力を入れている。
- 受賞: 山廃純米大吟醸がロバート・パーカーの評価で 95 点。山廃・山田錦が全国燗酒コンテスト 2024 金賞。シェフが選ぶ美酒アワードも複数。
- 海外: 香港、台湾、インド、フランス、ドイツ。英語サイト、SNS、オンライン商談に取り組む。
- 蔵元直送の通販（BASE）があり、720ml 2 本用の贈答箱も売っている。

## 3. 前の検討から持っていける気づき

設計とは独立に、どの案でも効きそうなもの。

**言葉と見せ方**
- 日本酒を知らない人には、純米、吟醸、精米歩合、日本酒度などの用語を本文に出さない。詳細を開いた時だけにする。
- 味は「甘め〜すっきり辛め」「軽やか〜コクあり」のように両端に言葉を置き、5 段の点で見せると伝わる。
- 瓶の大きさは「四合瓶」ではなく、飲み方で伝える（例: 飲みきりサイズ、たっぷりサイズ）。
- 候補は「迷った時のおすすめ」を先頭に置き、あとは本人に読んで選ばせる形が好まれた。定番と、通好みの両方を出す。
- トーンはすべて丁寧語にすると決めていた。見た目はギフト EC 風の白地に藍の差し色、書体は Zen Kaku Gothic New。

**LINE で贈る・受け取る時の注意**
- 共有は「文章ごとコピー」だけが好まれた。OS の共有シートは送り先を間違えそうで不安、という意見。
- 贈った人は、相手とのトークに残ったリンクを自分で開いて状況を見る。「贈ったものの一覧」はあまり見ない。
- リンクのページは、受け取る人と贈った人のどちらが開いても成り立つ言葉にする。
- LINE のリンクプレビューやスキャナが人より先にリンクを開くので、ページを開いただけで状態が変わる作りにしない。
- プレビュー（OGP）はグループのトークでも見えるので、名前や一言を出さない。
- 「取り消し」は強い言葉。「キャンセル」にする。期限切れやキャンセルは、受け取る側に同じ穏やかな文面を出す。断るボタンは置かない。

**受け取った後**
- 感想は本人だけのもの。贈った人に届くのは「開けたよ」の事実だけ。
- 「開けたよ」は、もらったお酒に感想を書いたら自動で届く形が好まれた。書く画面では告知せず、設定でオフにできる。
- 「また飲みたい」を選んだ人を蔵元直送の通販へ案内すると、蔵の売り上げにつながる。会長の講評で響きそうな点。

**お金と法律**
- 酒を仕入れて売るには酒販免許が要る。注文を仲介して代金を預かる形も免許に触れうる。
- ハッカソンでは「すべてデモ。決済も購入も発送もしない」が安全で、そう決めていた。
- 酒の購入につながる画面には「20歳未満の者の飲酒は法律で禁止されています」を置く。

**名前**
- 「ヒロポン」は戦後の覚醒剤の商品名なので使わない。
- 酒器になぞらえた候補: じゃのめ便（利き猪口の底の藍の二重丸。見極めて贈る、と便／瓶をかけた）、ききちょこ、おちょこ便、ぎんぞう（吟味して贈る）、いっこん（一献差し上げる）。
- 「じゃのめ」の藍の二重丸は、藍の差し色やロゴと合わせやすい。

## 4. 技術の前提と、試して分かったこと

**本人の前提**
- 手元は iPhone と PC。Mac はない。TypeScript だけで作りたい。
- アプリは Expo Go で動かすだけで、ストアには出さない。Expo Go では Android のプッシュ通知、Universal Links、ソーシャルログインが使えないか難しい。
- 主な連絡手段は LINE。

**70 分で作るなら**
- アプリ、API、DB、ログインまで含む構成は 70 分では無理。Web だけの縮小版か、企画書とクリックできるモックが現実的。

**Cloudflare の新しい CLI（cf、ベータ）で分かったこと**
- `cf init`、`cf dev`、`cf build`、`cf deploy` で Hono と D1 の Worker は動いた。設定は `cloudflare.config.ts`。
- Node 22.18 以上が必要。Bun では動かない。
- `cf dev` は Vite の 5173 番で動き、`--port` などの引数は通らない。ポートや LAN 公開は `vite.config.ts` の `server` で指定する。
- `cf d1 ... --local` は D1 を UUID でしか指定できない。開発用の D1 バインディングに固定の UUID を与えると、`cf dev` と `cf d1 migrations apply --local` が同じローカル DB を指す。
- `wrangler tail` と `wrangler secret put` に当たるものがまだない。ログは wrangler を併用し、秘密情報は `cf deploy --secrets-file` で渡す。
- React Router 8.4 を `cf build` でビルドすると、マニフェストの場所の食い違いで失敗する。Vite の小さなプラグインで回避できたが、Hono だけなら問題は起きない。
- Worker 同士のサービスバインディングを `cf dev` 同士で使うには、両方の `@cloudflare/vite-plugin` を同じ 2.0 ベータにそろえる必要があった。
- 開発時、相手の Worker の起動直後の 1〜2 リクエストが「Network connection lost」で落ちることがある。GET だけ 1 回再試行すると安定した。
- 開発時、相手の Vite 開発サーバーが Host を検査するので、hono/client の基準 URL は `http://localhost` にする。
- このクラウド環境ではプロキシの環境変数があると開発サーバー同士の通信が失敗した。開発サーバーを起動する時だけプロキシの変数を外すと通った。

**Expo SDK 57 と pnpm**
- Expo SDK 57 は pnpm の isolated な node_modules で動く。hoisted にすると cf の Vite プラグインが見つからなくなった。
- Expo の型チェックの前に一度 `expo start` を動かし、`expo-env.d.ts` を作っておく必要がある。
- hono/client の `hc<AppType>()` で API の型をアプリと Web から使えた。API 側で型定義を出力して読ませると、Workers とアプリの型が衝突しない。

## 5. 価格の一般的な相場（日本酒全般）

- 300ml の小瓶は 500〜2,000 円にほぼ収まる。720ml の手頃な定番は 1,200〜2,200 円、贈答の定番は 3,300〜5,000 円。
- 友人へのカジュアルな贈りものは 3,000〜5,000 円が目安とする記事が多い。

## 6. 新しいセッションで最初に決めること

1. 課題をどれにするか。前の検討からは「飲んだことがない人に薦める」と「若い人が手に取る理由をつくる」が近い。
2. 事前に作り込んでよいか（主催に確認）。
3. 成果物の形。Web だけの縮小版、モックと企画書、診断ツールなど。

## 7. 進め方の好み

- 選択肢を並べて、おすすめを 1 つ添えると決めやすい。
- 決めたことはその場で文書に残し、矛盾しないように保つ。
- ハッカソンなので、法務や物流などは「デモでは扱わない」と割り切ってよい。

## 8. このリポジトリの今の状態

- pnpm と Turborepo のモノレポで、Expo（apps/mobile）、Hono と D1 の API（apps/api）、Hono JSX の Web（apps/web）、Zod の共有スキーマ（packages/shared）の骨組みがある。型チェックとビルドは通る。
- `docs/` に前の設計（決定事項 D1〜D28、画面設計など）が残っている。新しい案では参考程度に使う。
